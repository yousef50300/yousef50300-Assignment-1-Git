# شرح `git filter-repo`

## إيه هو `git filter-repo`؟

`git filter-repo` هي أداة بستخدمها علشان أعدّل تاريخ المشروع، مش الملفات الحالية بس.

يعني لو ملف اتضاف في `Commit` قديم وبعد كده مسحته بالطريقة العادية، الملف هيختفي من النسخة الحالية، لكنه هيفضل موجود في الـ `Commits` القديمة. هنا بييجي دور `git filter-repo`، لأنني أقدر أمسح الملف من تاريخ المشروع كله.

الأداة دي مش بتيجي مع Git بشكل افتراضي، وممكن أثبتها باستخدام:

```bash
pip install git-filter-repo
```

## مثال عملي

لنفترض إني رفعت ملف `.env` بالغلط، والملف كان فيه بيانات سرية.

لو استخدمت:

```bash
git rm .env
git commit -m "Remove .env file"
```

كده الملف اتمسح من النسخة الحالية بس، لكن لسه أقدر أرجعله من الـ `Commits` القديمة.

علشان أمسحه من تاريخ المشروع كله، أستخدم:

```bash
git filter-repo --path .env --invert-paths
```

معنى أجزاء الأمر:

- `--path .env` بيحدد الملف اللي عاوز أمسحه.
- `--invert-paths` معناه امسح المسار ده، وسيب باقي ملفات المشروع.

بعد تنفيذ الأمر، ملف `.env` هيتمسح من كل الـ `Commits` اللي كان موجود فيها.

## مثال على حذف فولدر

لو عندي فولدر قديم اسمه `storage/logs` وعاوز أمسحه من تاريخ المشروع كله، أكتب:

```bash
git filter-repo --path storage/logs/ --invert-paths
```

## ليه الأمر ده خطير؟

لأن الأداة بتعيد كتابة تاريخ المشروع، وده بيؤدي لتغيير الـ `Commit Hashes`.

كل `Commit` بيعتمد على محتواه وعلى الـ `Commit` اللي قبله، فلما أغيّر `Commit` قديم، الـ Hash بتاعه بيتغيّر، وغالبًا الـ Hashes بتاعة الـ `Commits` اللي بعده بتتغيّر هي كمان.

الموضوع بيكون أخطر في المشاريع الكبيرة اللي عليها فريق، لأن:

- باقي الفريق هيكون عنده التاريخ القديم.
- بعض الـ Branches والـ Tags ممكن تتأثر.
- الـ Pull Requests المفتوحة ممكن يحصل فيها مشاكل.
- هحتاج أرفع التاريخ الجديد باستخدام `Force Push`.

مثال:

```bash
git push origin --force --all
git push origin --force --tags
```

بعدها غالبًا باقي الفريق هيحتاج يعمل `Clone` جديد للمشروع، علشان يتعامل مع التاريخ الجديد من غير تعارضات.

## إمتى أستخدمه؟

بستخدم `git filter-repo` في حالات مهمة، زي:

- حذف ملف فيه Password أو API Key.
- حذف ملف كبير بوّظ حجم الـ Repository.
- حذف بيانات حساسة من الـ Commits القديمة.
- فصل فولدر من مشروع كبير وتحويله إلى Repository مستقل.

لكن لو الملف عادي ومش مهم إنه يفضل موجود في التاريخ القديم، مش محتاج أستخدم الأداة. أقدر أمسحه بالطريقة العادية باستخدام `git rm`.


## الخلاصة

`git filter-repo` أداة قوية بستخدمها لتعديل تاريخ Git بالكامل.

الفرق الأساسي إن:

```bash
git rm .env
```

بيمسح الملف من النسخة الحالية فقط، أما:

```bash
git filter-repo --path .env --invert-paths
```

فبيمسحه من النسخة الحالية ومن الـ `Commits` القديمة كمان.

علشان كده لازم أستخدم الأداة بحذر، خصوصًا لو المشروع كبير أو عليه أكتر من شخص.
