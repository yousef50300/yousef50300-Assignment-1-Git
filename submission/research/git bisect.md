# Git Bisect

## إيه هو `git bisect`؟

أمر `git bisect` بستخدمه علشان أعرف أول `Commit` سببت مشكلة في المشروع.

الأمر بيعتمد على فكرة **Binary Search**، يعني مش بيراجع الـ Commits واحدة واحدة، لكنه في كل مرة بيختار Commit موجودة في نص نطاق البحث.

بختبر الـ Commit دي وبحدد نتيجتها:

```text
good = النسخة سليمة
bad  = المشكلة موجودة
```

بناءً على النتيجة، Git بيستبعد نص الـ Commits ويكمل البحث في النص التاني.

مثلاً لو عندي التاريخ ده:

```text
A — B — C — D — E — F — G
```

وعارف إن:

```text
A = good
G = bad
```

Git هيبدأ باختبار `D` لأنها موجودة في النص.

لو `D` سليمة، هيستبعد:

```text
A — B — C — D
```

ويكمل البحث بين:

```text
E — F — G
```

أما لو `D` فيها المشكلة، هيستبعد الجزء اللي بعدها، ويكمل البحث بين:

```text
A — B — C — D
```

بالطريقة دي، لو عندي 100 Commit، مش لازم أختبرهم كلهم. غالبًا هحتاج حوالي 7 اختبارات بس علشان أوصل لأول Commit سببت المشكلة.

## طريقة الاستخدام

ببدأ عملية البحث:

```bash
git bisect start
```

بحدد إن النسخة الحالية فيها المشكلة:

```bash
git bisect bad
```

بعدها بحدد Commit قديمة متأكد إن المشروع كان شغال عندها:

```bash
git bisect good commit-hash
```

مثال:

```bash
git bisect good a1b2c3d
```

بعد كده Git هينقلني تلقائيًا إلى Commit في نص نطاق البحث.

لو اختبرت المشروع ولقيته شغال:

```bash
git bisect good
```

ولو المشكلة موجودة:

```bash
git bisect bad
```

بكرر الاختبار لحد ما Git يحدد أول Commit سببت المشكلة:

```text
81bd111 is the first bad commit
```

ممكن أشوف تفاصيلها باستخدام:

```bash
git show 81bd111
```

## إنهاء العملية

بعد ما أخلص، بكتب:

```bash
git bisect reset
```

الأمر ده بينهي عملية البحث ويرجعني للمكان اللي كنت واقف فيه قبل ما أبدأ.
